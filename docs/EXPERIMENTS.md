# Experiment protocol

| ID | Hypothesis | Method | Required evidence |
|---|---|---|---|
| E01 | UE can register | Start core, gNB, UE; check AMF logs | Registration logs and NAS/NGAP pcap |
| E02 | UE can establish PDU session | Inspect SMF/UPF and UE TUN | Session logs, UE IP and routing table |
| E03 | User-plane connectivity works | Run ping from UE namespace or tunnel | Raw ping output and CSV |
| E04 | Throughput is measurable | Run controlled iperf3 client/server across UE path | Raw iperf3 JSON |
| E05 | Recovery can be characterized | Restart one selected NF under controlled conditions | Timestamped before/after logs and recovery time |

## Example measurements

From the **actual UE namespace/container** (adjust to the upstream deployment):

```bash
ping -n -c 20 -I <UE_TUN_INTERFACE> <REACHABLE_TEST_IP>
iperf3 -c <CONTROLLED_SERVER_IP> -t 20 -J > iperf3.json
```

Never substitute host-side ping for UE user-plane connectivity. Record whether tests are intra-host, LAN or Internet and whether traffic is NATed.

For RTT summary from a CSV generated by `benchmark.sh`:

```bash
python3 scripts/analyze_kpis.py --ping results/ping.csv --sent 20 --out results/summary.json
```

For iperf3 JSON add `--iperf path/to/iperf3.json`.
